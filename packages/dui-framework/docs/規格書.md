# @dui/framework 規格書

> 最後更新：2026-08-03

---

## 1. 套件概述

`@dui/framework` 是 WebCube2027 管理型 Gateway 的**共用框架套件**。提供 Gateway 啟動引導（`createGateway()`）、HTTP 框架（Hono）、檔案路由載入器（`loadRoutes()`），並統一管理 CSS 框架（TailwindCSS v4 + daisyUI v5）的依賴版本。

管理型 Gateway（ai、page、cube、theme、data、auth）共用此套件，確保依賴版本一致，不需各自管理。

---

## 2. 職責範圍

### 2.1 在範圍內

- Gateway 啟動引導（`createGateway()`）
- 檔案路由系統（`loadRoutes()`）
- 權限工具模組（`permission.ts`：角色權限型別與合併/檢查函式）
- 統一匯出 Hono 核心
- 管理 TailwindCSS 與 daisyUI 的依賴版本

### 2.2 不在範圍內

- 不包含業務邏輯
- 不包含路由定義（路由由各 Gateway 自行定義）
- 不包含樣式配置（tailwind.config、daisyUI 主題等由各 Gateway 自行配置）

## 3. 匯出項目

### 3.1 `mod.ts` — 主要入口

```typescript
export { createGateway } from '@dui/framework';
export type { CreateGatewayOptions, Gateway, MiddlewareFn } from '@dui/framework';
export { Hono } from 'hono';
```

`createGateway()` 是 Gateway 的統一啟動入口，處理以下初始化：

1. **資料目錄** — 計算 `data/` 目錄絕對路徑
2. **Hono 應用程式** — 建立 HTTP server
3. **檔案路由** — 自動載入 `{dirname}/routes/` 目錄下的 handler，並以 `runHandlerChain()` 最佳化 middleware 執行（取代 inline 閉包，減少 GC 負擔）。**loadRoutes 的結果直接作為 Hono app**（不包 `app.route()`）——Hono 的 `route()` 只複製子 app 的 routes、不繼承 notFoundHandler，而階層降級退回（見第 5 章）正是住在 notFound 中，包裝會使其靜默失效

> ConfigStore 與加密金鑰管理已移至 `@dui/util`（`ConfigStore` / `registerKey`），各 Gateway 自行在 `main.ts` 中管理。

| 匯出名稱 | 來源 | 型別 | 說明 |
|---------|------|------|------|
| `createGateway` | 本地 | function | Gateway 啟動引導，回傳 `Gateway` 物件 |
| `Gateway` | 本地 | interface | `{ app, dataDir, port, start() }` |
| `CreateGatewayOptions` | 本地 | interface | `{ name, port?, dirname }` |
| `MiddlewareFn` | `route-loader.ts` | type | `(c: Context, next: Next) => Promise<Response \| void>` |
| `Hono` | `hono` | class | Web 框架核心類別 |
| `mergePermissions` | `permission.ts` | function | 合併多個角色的權限（取最寬鬆） |
| `checkAccess` | `permission.ts` | function | 依 JWT payload 檢查操作權限（含 self 比對） |
| `checkPermission` | `permission.ts` | function | 取得指定 collection 的權限值 |
| `extractCollection` | `permission.ts` | function | 從 composite ID 提取 collection 名稱 |
| `PermissionMap` / `LevelPermission` / `CollectionPermission` / `PermissionValue` | `permission.ts` | type | 角色權限資料型別 |

### 3.2 使用方式

```typescript
import { createGateway, Hono } from '@dui/framework';

const gw = await createGateway({
  name: 'my-gateway',
  port: 8000,
  dirname: import.meta.dirname!,  // ← 傳入 Gateway 自身目錄
});

// gw.app   — Hono 實例（已載入檔案路由）
// gw.dataDir — data/ 目錄絕對路徑
// gw.port  — HTTP 監聽埠

gw.start();
```

### 3.3 `loadRoutes()` — 檔案路由系統

```typescript
import { loadRoutes } from '@dui/framework/route-loader';
```

掃描 `routes/` 目錄，自動載入 handler 與靜態檔案。

**支援的檔案類型：**

| 類型 | 檔名 | 行為 |
|------|------|------|
| Method handler | `get.ts`, `post.ts`, `put.ts`, `del.ts`, `patch.ts` | 匯出對應 method 的 handler 函數；**不包裹 Layout** |
| 目錄首頁 | `index.tsx` | 視為 GET handler。若 export **default** 元件，且 routes/ 下存在 `_layout.tsx`，則**自動用 Layout 包裹** |
| `.tsx` 頁面元件 | `foo.tsx`（非 method 名） | export default 元件 → 自動用 `_layout.tsx` 的 `Layout` 包裹（若存在） |
| `.md` 文件 | `*.md` | Markdown 自動轉 HTML（透過 `marked`）。使用 `_layout.tsx` 的 `renderPage()` 渲染（若存在），否則使用預設模板 |
| 靜態檔案 | `.css`, `.js`, `.svg`, `.jpg`, `.png`, `.webp` | 自動以 GET 服務，含正確 Content-Type |

**關於 `_layout.tsx` 的自動包裹行為**：

- **`.tsx` 頁面 export default 元件** → route-loader 以 `jsx(layoutMod.Layout, { title, lang, children })` 包裹，並呼叫 `renderToString()` 轉為 HTML 字串
- **`.md` 文件** → route-loader 呼叫 `layoutMod.renderPage(title, htmlContent, lang)` 取得完整 HTML
- **Method handler（如 `get.ts`）** → 直接使用，**不進行任何包裹**，因為 API handler 不應有 HTML 外殼
- 若 `_layout.tsx` 不存在，.md 頁面使用內建預設模板（含 TailwindCSS prose），.tsx 頁面退而使用 `mod[route.method]` 或 `mod.default` 原始行為
| 中間件 | `_middleware.ts` | 匯出 `middleware`（或 `default`）函數，套用至該目錄所有路由 |

**目錄命名規則：**
- `foo/` → 靜態路徑段落 `/foo`
- `_name_/` → 動態參數 `/:name`

**支援的 middleware：**

```typescript
import type { MiddlewareFn } from '@dui/framework/route-loader';

// middleware 可為 sync 或 async，回傳 Response 則中斷鏈路
const middleware: MiddlewareFn = async (c, next) => {
  // 到達 handler 前
  await next();
  // handler 回傳後
};
```

> **路由退回機制**：`loadRoutes()` 另提供 Pass 3 階層降級退回（Fallback）機制，詳細演算法見第 5 章。

### 3.4 `api-console` — 共用前端 JavaScript

```typescript
import { API_CONSOLE_SCRIPT } from '@dui/framework/api-console';
```

提供服務狀態監控（`loadStatus`）與 API 測試工具（`sendApiRequest`）的前端 script 字串，供各 Gateway 管理後台以 `<script>{raw(API_CONSOLE_SCRIPT)}</script>` 嵌入。

- 所有輸出皆使用 `textContent`（無 `innerHTML`），避免 XSS
- 初始化以 `document.readyState === 'loading'` 判斷 DOM 就緒：若頁面動態載入（SPA 換頁 / AJAX 注入）時 `DOMContentLoaded` 已過，則立即執行初始化，確保監聽器與 `loadStatus()` 生效

### 3.5 `permission` — 權限工具模組

```typescript
import { mergePermissions, checkAccess, checkPermission, extractCollection } from '@dui/framework';
```

角色權限（Role Permission）的共用型別與工具函式，供各 Gateway 直接使用，避免各自維護複本：

- **`mergePermissions(roles)`** — 合併多個角色的權限（取最寬鬆）。auth-gateway 的 `/api/verify-user` 在本端彙整使用者各角色的權限即使用此函式。
- **`checkAccess(payload, level, collection, action, authorId?)`** — 依 JWT payload 判斷操作是否允許（支援 `true` / `false` / `'self'`）。適用於需要角色權限判斷的 Gateway（如未來的 WebCube 前端服務）。
- **`checkPermission(permissions, level, collection, action)`** — 取得指定 collection 的權限值（不帶 authorId 比對）。
- **`extractCollection(id)`** — 從 composite ID（`collection:model:nanoid`）提取 collection 名稱。
- 型別：`PermissionMap` / `LevelPermission` / `CollectionPermission` / `PermissionValue`。

此模組**無相依、純 TypeScript**，不包含任何業務邏輯。

> 權限模型的分工：data-gateway 為純資料層，不解析角色權限（僅以 `X-API-Key` collection 權限表管控）；角色權限的合併與驗證由 auth-gateway 在本端進行。

## 4. 檔案路由系統

`loadRoutes()` 是 route-loader 的核心，掃描 `routes/` 目錄並自動將檔案結構映射為 HTTP 路由。**所有 Gateway 共用此系統**，路由結構在不同 Gateway 間保持一致。

### 4.1 檔案命名 → HTTP Method 對應表

| 檔名 | HTTP Method | 行為 |
|------|-------------|------|
| `get.ts` | `GET` | 匯出 `GET` 函式即註冊為 GET handler |
| `post.ts` | `POST` | 匯出 `POST` 函式即註冊為 POST handler |
| `put.ts` | `PUT` | 匯出 `PUT` 函式即註冊為 PUT handler |
| `del.ts` | `DELETE` | 匯出 `DELETE` 函式即註冊為 DELETE handler |
| `patch.ts` | `PATCH` | 匯出 `PATCH` 函式即註冊為 PATCH handler |
| `index.tsx` / `index.ts` | `GET` | 目錄預設頁面，視為 GET handler |
| `*.md` | `GET` | Markdown 自動轉 HTML（透過 `marked`） |

### 4.2 目錄命名規則

| 目錄名稱 | 路由效果 | 範例 |
|---------|---------|------|
| `foo/` | 靜態路徑段落 `/foo` | `users/` → `/users` |
| `_name_/` | 動態參數 `/:name` | `_id_/` → `/:id` |
| `_lang_/` | **特殊保留目錄**：多國語言路由 | → 自動註冊語言偵測 redirect at `GET /`，其下所有路由加上 `/:lang` 前綴 |

> `_lang_` 是保留目錄名稱，僅在 `routes/` 根目錄有效。偵測到 `_lang_` 目錄時，route-loader 會：
> 1. 在 `GET /` 自動註冊語言偵測 redirect（依 `Accept-Language` header 導向 `/:lang/`）
> 2. `_lang_` 目錄下的所有路由加上 `/:lang` 前綴（如 `_lang_/index.tsx` → `/:lang/`）

### 4.3 Middleware 系統

每個目錄可放置 `_middleware.ts`，匯出 `middleware`（或 `default`）函式：

```typescript
// routes/api/_middleware.ts
import type { Context, Next } from 'hono';

export const middleware = async (c: Context, next: Next) => {
  // 前置處理（到達 handler 前）
  const token = extractToken(c);

  if (!token) {
    return c.json({ error: '未提供 Token' }, 401);
  }

  await next();  // 繼續到下一個 middleware 或 handler

  // 後置處理（handler 回傳後）
};
```

**Middleware 疊加規則**：

```
routes/
├── _middleware.ts           ← 套用至 routes/ 下所有路由（全域）
├── api/
│   ├── _middleware.ts       ← 套用至 /api/*（在根 middleware 之後執行）
│   └── health/
│       └── get.ts           ← 套用全域 + api 兩層 middleware
└── _lang_/
    └── admin/
        ├── _middleware.ts   ← 套用至 /:lang/admin/*
        └── index.tsx        ← 套用全域 + admin 兩層 middleware
```

### 4.4 `_layout.tsx` — 共用頁面版型

若 `routes/` 根目錄存在 `_layout.tsx`，route-loader 會自動將其包裹 `.tsx` 頁面元件。

**`_layout.tsx` 由各 Gateway 自行定義**，框架不強制任何結構。每個 Gateway 應根據自身需求設計 navbar、footer 與版面佈局（例如 data-gateway 的 navbar 有登入/登出按鈕與服務狀態，auth-gateway 的 navbar 只有服務狀態 badge）。

**必要匯出**：

| 匯出名稱 | 用途 | 規格 |
|---------|------|------|
| `Layout` | 包裹 `.tsx` 頁面元件的 Hono JSX 元件 | 接收 `{ title, children, lang? }`，回傳完整 HTML（含 `<html>`、`<head>`、`<body>`） |
| `renderPage(title, content, lang?)` | 供 `.md` 頁面使用，回傳完整 HTML 字串 | 內部呼叫 `renderToString(jsx(Layout, ...))` |

> `lang` 參數由 route-loader 從 Context（`c.get('lang')`）自動傳入，預設為 `'zh-tw'`。`title` 從頁面元件的 `mod.title` 或 .md 內容萃取——`extractTitle` 會忽略開頭的 YAML Front Matter（避免 front matter 內的 `#` 行被誤判），並剝除標題內的 HTML 標籤。

**注意**：`.tsx` 頁面若 export `default` 元件，且 routes/ 下存在 `_layout.tsx`，**頁面元件不應再自行輸出 `<html>`、`<head>`、`<body>`**，這些由 Layout 統一提供。若 .tsx 頁面 export 的是 `GET` 函式（如 `export const GET = ...`），則不會被 Layout 包裹，適用於需要自訂 HTTP header 或非 HTML 回應的特殊頁面。

**範例結構**（data-gateway 實作參考）：

```typescript
// routes/_layout.tsx
import { renderToString } from 'hono/jsx/dom/server';
import { jsx } from 'hono/jsx';
import { raw } from 'hono/html';

export const Layout = ({ title, children, lang }) => {
  const prefix = `/${lang || 'zh-tw'}`;
  return (
    <html lang={lang || 'zh-TW'}>
      <head>
        <meta charset="UTF-8" />
        <title>{title}</title>
        <link href="/css/output.css" rel="stylesheet" />
      </head>
      <body>
        {/* ── Navbar（各 Gateway 自行設計）── */}
        <div class="navbar ...">
          <a href={`${prefix}/`}>Gateway 名稱</a>
          <div class="flex-none">
            <span id="status-badge" class="badge">檢查中…</span>
            <div id="nav-auth-container"></div>
          </div>
        </div>

        <main>{children}</main>

        <footer>WebCube2027 — Gateway 名稱</footer>

        {/* ── 共用 client-side script ── */}
        <script>{raw(STATUS_SCRIPT)}</script>
      </body>
    </html>
  );
};

// 供 .md 頁面使用的完整 HTML 渲染函式
// title 慣例：route-loader 已在呼叫前完成 HTML 跳脫（XSS 防護），
// 故以 raw() 標記為「已跳脫」，避免 Layout 的 JSX 再跳脫造成雙重跳脫。
export function renderPage(title: string, content: string, lang?: string): string {
  return '<!DOCTYPE html>' + renderToString(
    jsx(Layout, { title: raw(title), lang }, raw(content)),
  );
}
```

**Title 跳脫慣例（XSS 防護）**：

- route-loader 在呼叫 `renderPage()` 前，統一以 `escapeHtml()` 跳脫從 Markdown 萃取的 title（`& < > "` 一次到位）
- 各 layout 的 `renderPage` **不得再跳脫**——data/auth layout 以 `raw(title)` 標記（`raw` 會設 `isEscaped = true`，hono JSX 見 `isEscaped` 即不跳脫）；ai-gateway 這類純字串模板直接插入即可
- hono JSX 會自動跳脫字串子項與屬性，Layout 內寫 `{title}` 即可，**勿再包 `ehtml()`**（會造成雙重跳脫）

**運作方式**：
- `.tsx` 頁面 export default 元件 → route-loader 自動用 `Layout` 包裹
- `.md` 頁面 → route-loader 呼叫 `renderPage()` 取得完整 HTML
- 無 `_layout.tsx` 時，.md 頁面使用預設 HTML 模板

### 4.5 路由優先順序

當同一個路徑有多個匹配可能時，優先順序為：

```
.tsx 頁面 > .md 文件 > index.tsx > index.md
```

實例：若同時存在 `routes/profile.tsx` 和 `routes/profile.md`，`.tsx` 優先。

### 4.6 靜態檔案自動服務

副檔名符合以下條件的檔案會自動以 `GET` 服務（無需撰寫 handler）：

| 副檔名 | Content-Type |
|--------|-------------|
| `.css` | `text/css` |
| `.js` | `application/javascript` |
| `.svg` | `image/svg+xml` |
| `.jpg` / `.jpeg` | `image/jpeg` |
| `.png` | `image/png` |
| `.webp` | `image/webp` |

靜態檔案路由優先於 method handler 與 .md 路由。

**載入策略**：初始化時 route-loader 會預先讀取檔案內容並快取（避免每次請求重複讀檔）。**預載失敗時仍會註冊 GET 路由**，改為 runtime 逐次重讀（成功後寫回快取）——不能 `continue` 靜默失去路由。

### 4.7 Markdown Heading ID 自動生成

當 `.md` 文件透過 `marked` 轉為 HTML 後，route-loader 會**自動為所有 `<h1>` ~ `<h6>` 標籤加上 `id` 屬性**（若尚未擁有）：

- ID 生成規則：移除 HTML 標籤 → 轉為小寫 → 非單字/中文的字元替換為 `-` → 移除首尾 `-`
- 範例：`## Composite ID 格式` → `<h2 id="composite-id-格式">`
- 原有 `id` 屬性的標題不會被覆蓋

這使得 `.md` 頁面無需手動撰寫標籤即可支援目錄（TOC）的 anchor 連結。

> **title 萃取（`extractTitle`）**：先忽略開頭的 YAML Front Matter（`/^---[\s\S]*?---\s*/`），再取第一個 `#` 標題，並剝除 HTML 標籤（`/<[^>]*>/g`），確保 `<title>` 分頁列顯示純字串而非轉義字面。

### 4.9 建立新 Gateway 的路由規範

依循 data-gateway 模式，建立新的管理型 Gateway 時應遵循以下規則：

1. **`main.ts`** 使用 `createGateway()` 啟動，傳入 `dirname: import.meta.dirname!`
2. **`routes/_middleware.ts`** 定義全域 middleware（安裝檢查、JWT 驗證等）
3. **`routes/_layout.tsx`** 定義共用 HTML 版型（需匯出 `Layout` 元件與 `renderPage()` 函式）。navbar 內容依 Gateway 需求自行設計，框架不強制結構
4. **`routes/_lang_/`** 若有前端頁面，使用 `_lang_` 目錄支援多國語言（自動註冊語言偵測 redirect）
5. **`routes/api/`** API handler 使用 `get.ts` / `post.ts` 等檔名對應 HTTP method
6. **`routes/_xxx_/`** 動態路徑參數使用底線包圍（如 `_id_` → `/:id`）
7. **`routes/_middleware.ts`** 各目錄層級的 middleware 僅處理該層級及其子路徑的請求

## 5. 路由 Fallback 退回機制（階層降級退回）

當請求未命中任何精確路由時，route-loader 會進入 **Pass 3** 的 notFound handler，以**逐層剝皮**的方式退回母路由執行。這取代了舊有的 `/*` wildcard 做法——wildcard 會搶走精確靜態路由的匹配機會。

### 5.1 演算法

1. 請求未命中任何精確路由 → 進入 notFound
2. 將 URL 路徑從最深層開始，逐層去掉最後一段往上找
3. 若找到對應的母路由（method 相同），執行其 handler 並設 `rest_path`
4. 一路找不到（含根目錄 `/`，由 `i = 0` 涵蓋）才回傳 404

**範例**：`GET /api/使用者/角色/all` 無精確匹配 → 依序嘗試 `/api/使用者/角色` → `/api/使用者` → `/api` → `/` → 命中 `/api/:collection/:model` 的 handler，`rest_path = "all"`。

### 5.2 比對規則

| 比對 | 條件 | 說明 |
|------|------|------|
| 精確比對（`isExactMatch`） | 母路由為靜態路徑，且與剝皮後路徑完全相同（含尾綴斜線版本） | `/api/health` → `/api/health` |
| 動態參數比對（`isParamMatch`） | `patternSegs` 長度需等於剝皮層數（`patternSegs.length === i`），逐段比對並收集 `:param` 對應值 | `/api/:collection/:model` 匹配 `/api/網站/角色` → `collection=網站, model=角色` |

> `patternSegs.length === i` 是正確的邊界：若母路由與請求等長，Hono router 會直接命中，根本不會進入 notFound；fallback 只服務「母路由比請求短」的情況。

### 5.3 參數注入（param 遮蔽）

Hono 的 `HonoRequest.#matchResult` 是 hard-private 欄位，無法直接寫入；且 notFound 情境下 `#matchResult` 為空陣列，呼叫 `c.req.param()` 甚至會拋錯。因此 route-loader 以 **instance own property 暫時遮蔽** `c.req.param()`，將比對收集的動態參數注入 handler，並在 `try...finally` 中刪除還原：

```typescript
c.set('rest_path', restPath);
const req = c.req;
(req as any).param = (key?: string) => (key ? params[key] : params);
try {
  res = await runHandlerChain(ri.handlers, c);
} finally {
  delete (req as any).param; // 還原原型 param()
}
```

### 5.4 Context 複用

Fallback 命中時**直接複用原 Context**（不 `new Context`）：

1. 避免每次比對命中都建立新物件，減少 GC 壓力
2. 保留先前 middleware 存入的變數（如 `jwt_payload`、`effective_host` 等 `c.set()` 資料）

### 5.5 rest_path 慣例

Fallback 命中母路由時，剩餘路徑以 `c.set('rest_path', restPath)` 存放，由 handler 自行判斷。例如 `routes/api/sites/get.ts` 以 `restPath === 'all'` 區分 `GET /api/sites` 與 `GET /api/sites/all`。

### 5.6 效能

`patternSegs`（母路由的分段拆解）於初始化 Pass 1 時**預先拆好**存入 `methodRouteInfos`，避免 notFound 高頻觸發時重複 `split`/`filter`。

### 5.7 與 Middleware 的相容

Handler 鏈條透過 `runHandlerChain()` 執行（仿 Hono compose）：middleware 以 `await next()`（不回傳）串接時，handler 產生的 Response 會存入 `c.res`（setter 同步設 `finalized = true`），fallback 最後以 `c.finalized && c.res` 兜底取回應——避免 middleware 吞掉回傳值導致空回應。
