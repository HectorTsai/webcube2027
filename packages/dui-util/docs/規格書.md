# @dui/util 規格書

> 最後更新：2026-07-28

---

## 1. 套件概述

`@dui/util` 是 WebCube2027 的通用工具套件，提供跨所有 Gateway 共用的基礎設施：

- **Crypto** — AES-256-GCM 加解密（v2 格式：直接 AES-GCM，無 PBKDF2 開銷）
- **JWT** — 跨 Gateway 共用 JWT 驗證工具（靜態導入 hono/jwt，Typed Context）
- **SecretString** — 自動加解密字串包裝器（含併發安全保護）
- **gwFetch** — 跨 Gateway HTTP 客戶端（自動攜帶語言、租戶、身份與 Trace ID）
- **InnerAPI** — 內部服務間通訊代理（附 Request 級別快取，保留原始 Response Headers）
- **Logger** — 日誌記錄工具（含序列化檔案寫入佇列防併發鎖定，支援 Trace ID）
- **Response** — 統一 API 回應型別與建構函式

## 2. Crypto — 加解密工具

### 2.1 概述

提供 AES-256-GCM 加解密功能，用於保護 L1 連線資訊等敏感資料。

**v0.4.0 重要優化**：
- 新加密資料使用 `enc:v2` 格式：直接以 256-bit 十六進位金鑰導入 AES-GCM，**完全跳過 PBKDF2**（節省 100K 疊代 CPU 開銷）
- CryptoKey 模組層級快取，後續呼叫直接重用，無重複匯入金鑰開銷
- `enc:v1` 格式（PBKDF2 衍生）仍完整支援解密，向後相容既有資料
- `@std/encoding/base64` 取代手動 `btoa` + `fromCharCode`
- `@std/path` 的 `dirname()` 取代手動路徑截取（跨平台相容）

金鑰解析順序：
1. **`CRYPTO_KEY` 環境變數**（由 `registerKey()` 或 `createGateway()` 設定）
2. **`SECRET_KEY` 環境變數**（production 佈署用）
3. **`./data/.crypto.key` 檔案**（第一次執行自動產生，重啟後有效）
4. **自動產生** — 256-bit 隨機金鑰，寫入 `./data/.crypto.key`

### 2.2 方法

| 方法 | 說明 |
|------|------|
| `encrypt(value)` | 加密字串，回傳 `enc:v2\|...` 格式的 Base64 字串 |
| `decrypt(value)` | 解密字串，支援 `enc:v1`（PBKDF2 舊格式）與 `enc:v2`（直接 AES-GCM 新格式）。非 `enc:` 前綴的值視為明文穿透 |
| `registerKey(hexKey)` | 程式化註冊加密金鑰（設定 CRYPTO_KEY env var + 模組快取） |
| `ensureKey(keyDir?)` | 確保加密金鑰存在（啟動時呼叫，可指定目錄路徑） |

### 2.3 v1 vs v2 格式

| 版本 | 格式 | 金鑰衍生 | 效能 |
|------|------|---------|------|
| `enc:v2`（新版） | `enc:v2\|b64(iv)\|b64(cipher)` | 直接 AES-GCM 匯入 | **即時**，無 PBKDF2 |
| `enc:v1`（舊版） | `enc:v1\|b64(iv)\|b64(salt)\|b64(cipher)` | PBKDF2 100K 疊代 | 慢，每次約 100ms |

舊版 `enc:v1` 解密時自動以 `(hexKey, salt)` 為鍵快取衍生金鑰，重複解密同一資料不需重跑 PBKDF2。

### 2.4 使用範例

```typescript
import { encrypt, decrypt, ensureKey } from '@dui/util';

// 啟動時確保金鑰
ensureKey();

// 加密（v2 格式，無 PBKDF2）
const encrypted = await encrypt('敏感資料');

// 解密（自動辨識 v1/v2）
const decrypted = await decrypt(encrypted);
```

## 3. JWT — 跨 Gateway 共用驗證工具

### 3.1 概述

提供各 Gateway（data、ai、page、cube、theme 等）驗證 auth-gateway 簽發之 JWT 的共用工具。

可透過環境變數 `AUTH_GATEWAY_URL` 設定 auth-gateway 位置，或透過程式化 `setAuthGatewayUrl(url)` 函式指定。首次呼叫時向 auth-gateway 取得 Ed25519 公鑰並快取在記憶體。支援**金鑰輪換**（驗證失敗時自動清除快取重新取得）。

### 3.2 方法

| 匯出名稱 | 簽名 | 說明 |
|---------|------|------|
| `extractToken(c)` | `(c: Context) => string` | 從 request 提取 JWT token（依序：query param → cookie → Authorization: Bearer） |
| `verifyToken(token)` | `<T>(token: string) => Promise<T \| null>` | 驗證 JWT token (Ed25519/EdDSA)，成功回傳泛型 payload，失敗回傳 `null`。內建金鑰輪換支援 |
| `寫入Cookie並重導(c, token, url)` | `(c: Context, token: string, url: URL) => Response \| null` | 將 token 寫入 HttpOnly cookie 後重新導向（移除網址上的 token 參數） |

### 3.3 相依關係

| 依賴 | 用途 |
|------|------|
| 環境變數 / 程式化設定 | `AUTH_GATEWAY_URL` 環境變數或 `setAuthGatewayUrl(url)` 函式 |
| `hono/jwt` | JWT 驗證（`verify` 函式，靜態頂層導入） |
| `hono` | `Context` 型別（取代 `any`） |

### 3.4 注意事項

- `fetchPublicKey` 的快取是模組層級全域共用，所有使用 `verifyToken` 的 handler 共享同一個公鑰快取
- 若 auth-gateway 更換金鑰對，`verifyToken` 在下次驗證失敗時會自動清除快取並重新取得
- 使用此模組的 Gateway 可透過環境變數 `AUTH_GATEWAY_URL` 或呼叫 `setAuthGatewayUrl(url)` 設定 auth-gateway 位置
- `extractToken` 與 `寫入Cookie並重導` 使用 Hono `Context` 型別取代舊有的 `any`，提供編譯期型別安全

## 4. ConfigStore — 設定儲存

### 4.1 概述

`ConfigStore` 提供輕量級的持久化 KV 儲存，以 JSON 檔案為後端儲存媒體。用於 Gateway 實例的設定管理（加密金鑰、連線資訊、URL 等）。

所有資料快取在記憶體中以提供快速讀取。寫入使用髒標記合併（dirty-flag coalescing）+ 原子暫存檔 + 重新命名模式，防止檔案損毀。

> ConfigStore **不是資料庫** — 僅適用於輕量設定儲存。結構化資料應使用 `@dui/database`。

### 4.2 建構子

| 參數 | 型別 | 說明 |
|------|------|------|
| `dataPath?` | `string` | JSON 檔案路徑，預設為 `./data/config.json`（可經由 `CONFIG_PATH` 環境變數覆寫） |

### 4.3 方法

| 方法 | 簽名 | 說明 |
|------|------|------|
| `init()` | `() => Promise<void>` | 初始化儲存 — 確保目錄存在並載入現有資料 |
| `get(key)` | `(key: string) => Promise<string \| null>` | 讀取設定值，不存在時回傳 `null` |
| `set(key, value)` | `(key: string, value: string) => Promise<void>` | 寫入設定值（非同步持久化，含髒標記合併） |
| `delete(key)` | `(key: string) => Promise<void>` | 刪除設定值（非同步持久化） |
| `has(key)` | `(key: string) => boolean` | 檢查 key 是否存在（同步，僅查記憶體快取） |
| `keys()` | `() => string[]` | 取得所有 key（同步） |
| `exportAll()` | `() => Record<string, string>` | 匯出所有資料為純物件（供備份 / Admin UI 使用） |

### 4.4 使用範例

```typescript
import { ConfigStore } from '@dui/util';

const store = new ConfigStore('./data/config.json');
await store.init();
await store.set('auth_gateway_url', 'http://localhost:8001');
const url = await store.get('auth_gateway_url'); // "http://localhost:8001"
```

### 4.5 注意事項

- 建構子**不會**自動載入資料 — 必須在啟動流程中呼叫 `await store.init()`
- 寫入使用背景任務合併（dirty-flag coalescing），多個併發 `set()` / `delete()` 共享同一次磁碟寫入
- 使用原子寫入模式（暫存檔 + `Deno.rename`），避免寫入中途崩潰導致檔案損毀

## 5. SecretString — 自動加解密字串包裝器

### 5.1 概述

`SecretString` 是一個自動加解密的字串包裝器，適合 Model 中儲存密碼或金鑰。

**v0.4.0 優化**：`process()` 加入**併發安全保護**，同時多個 `getPlainText()` / `getCipherText()` 呼叫共享同一個 in-flight promise，避免重複加解密 CPU 開銷。

### 5.2 方法

| 簽名 | 說明 |
|------|------|
| `new SecretString({ plainText? })` | 以明文初始化（寫入時自動加密） |
| `new SecretString({ cipherText? })` | 以密文初始化（讀取時自動解密） |
| `getPlainText(): Promise<string>` | 取得解密後的明文 |
| `setPlainText(text): Promise<void>` | 設定新明文（自動加密） |
| `getCipherText(): Promise<string>` | 取得加密後的密文 |
| `setCipherText(text): Promise<void>` | 設定現有密文（自動解密） |
| `process(): Promise<void>` | 同步明文與密文（併發安全） |
| `PlainText` getter/setter | 同步明文（僅在 `process()` 後有效） |
| `CipherText` getter/setter | 同步密文（僅在 `process()` 後有效） |

### 5.3 使用範例

```typescript
import { SecretString } from '@dui/util';

const secret = new SecretString({ plainText: 'my-api-key' });
const plain = await secret.getPlainText();   // "my-api-key"
const enc = await secret.getCipherText();    // "enc:v2|..."
```

## 6. InnerAPI — 內部 API 代理

### 6.1 概述

InnerAPI 是 Gateway 之間進行 HTTP 內部通訊的代理機制。所有管理型 Gateway 透過 InnerAPI 向 `data-gateway` 發起資料請求，不直接暴露外部埠號。

核心特性：**Request 級別透明快取**，同一個請求在相同 Context 內只會執行一次。

**v0.4.0 優化**：
- 快取命中時**保留原始 Response Headers**（Set-Cookie、自訂 Header 等），透過 `Object.fromEntries(response.headers.entries())` 儲存與回放
- URL 解析使用 `new URL(apiPath, 'http://localhost')` 安全正規化路徑，避免 `URLSearchParams` 重複編碼問題

### 6.2 方法

| 方法 | 簽名 | 說明 |
|------|------|------|
| `設定App(app)` | `(app: any) => void` | 啟動時注入 Hono app 實例，供 InnerAPI 內部路由使用 |
| `InnerAPI(c, apiPath)` | `(c: Context, apiPath: string) => Promise<Response>` | 發起內部 API 請求，回傳 `Response` |
| `取得域名(c)` | `(c: Context) => string` | 從 Context 解析目前請求的 hostname（不含埠號） |

### 6.3 快取機制

```
InnerAPI(c, "/api/settings")
  → 檢查 c.get("api_internal_cache") 是否有對應路徑
    → 命中：以快取的 headers + data 重建 Response（保留原始 Set-Cookie 等）
    → 未命中：執行內部請求 → 讀取 JSON body → 快取 { data, headers } → 回傳原始 Response

快取生命週期：僅限單一 HTTP Request 的 Context
同一請求內多次呼叫相同路徑只會查詢一次資料庫
```

### 6.4 使用範例

```typescript
import { Hono } from 'hono';
import { InnerAPI, 設定App } from '@dui/util';

const app = new Hono();
設定App(app);  // 啟動時注入

app.get('/page', async (c) => {
  const data = await InnerAPI(c, '/api/網站資訊/example.com');
  // 在 render-gateway 內，這會呼叫 data-gateway 的內部路由
  return c.json(data);
});
```

### 6.5 注意事項

- 必須在 `main.ts` 啟動流程中呼叫 `設定App(app)`，否則 InnerAPI 會拋出錯誤
- 內部請求會自動帶入原始請求的 `cookie`、`host`、`origin` header
- 非 JSON 回應不會被快取（保留原始 Response 不回讀 body）

## 6.6 跨 Gateway HTTP 客戶端（gwFetch）

### 6.6.1 概述

`gwFetch()` 是跨 Gateway HTTP 呼叫的統一客戶端，封裝 Deno 原生 `fetch`，**自動攜帶當前請求的 Context 資訊**，使目標 Gateway 能正確識別來源請求的語言、租戶、身份與追蹤碼。

### 6.6.2 自動攜帶的 Headers

| Header | 來源 | 說明 |
|--------|------|------|
| `Accept-Language` | `c.get('lang')` | 目前請求的語言 |
| `X-Tenant` | `c.get('tenant')` | 目前請求的租戶 |
| `Cookie` | `c.req.header('Cookie')` | 維持 JWT 登入狀態 |
| `X-Request-ID` | `c.get('trace_id')` | **Trace ID**，使分散式呼叫鏈可串接 |
| `Content-Type` | 自動（若未指定且有 body） | 預設 `application/json` |

### 6.6.3 簽名

```typescript
gwFetch(c: Context, baseUrl: string, path: string, options?: RequestInit): Promise<Response>
```

### 6.6.4 使用範例

```typescript
import { gwFetch } from '@dui/util';

// 在 API handler 中
const res = await gwFetch(c, dataGatewayUrl, '/api/l2/使用者/使用者');
const json = await res.json();
```

## 7. Logger — 日誌記錄

### 7.1 概述

Logger 提供統一的日誌記錄介面，支援層級過濾與選擇性檔案寫入。

**v0.4.0 優化**：導入**序列化寫入佇列**（Promise chain），高頻併發日誌寫入時依序執行，避免 `ResourceBusy` 磁碟鎖定錯誤。

**v0.5.0 新增**：支援 **Trace ID** 自動輸出。Logger 可透過 `AsyncLocalStorage` 或顯式參數取得當前請求的 `trace_id`，若存在則自動附加至日誌輸出格式中。

### 7.2 Trace ID 支援

Logger 提供兩種方式將 trace ID 納入日誌：

1. **Context 自動擷取**（推薦）：Logger 內部使用 `node:async_hooks` 的 `AsyncLocalStorage`，在 `@dui/framework` 的 Trace ID middleware 中以 `traceStorage.run(traceId, () => next())` 包裹，Logger 自動從儲存中讀取當前請求的 `trace_id`
2. **顯式傳入**：各方法接受選填第三參數 `traceId?: string`

輸出格式（trace ID 存在時）：
```
[2026-08-05 10:30:00] [INFO] [a1b2c3d4] [模組名稱] 訊息內容
```

無 trace ID 時維持原格式：
```
[2026-08-05 10:30:00] [INFO] [模組名稱] 訊息內容
```

### 7.3 環境變數配置

| 變數 | 預設值 | 說明 |
|------|--------|------|
| `LOG_LEVEL` | `info` | 日誌過濾層級：`debug` / `info` / `warn` / `error` |
| `LOG_TO_FILE` | `false` | 設為 `true` 啟用檔案輸出，寫入 `./logs/app.log` |

### 7.4 方法

| 方法 | 說明 |
|------|------|
| `logger.debug(模組, 訊息, traceId?)` | 除錯日誌，可選 trace ID |
| `logger.info(模組, 訊息, traceId?)` | 一般資訊 |
| `logger.warn(模組, 訊息)` | 警告 |
| `logger.error(模組, 訊息)` | 錯誤 |
| `debug(模組, 訊息)` | 全域便捷函式 |
| `info(模組, 訊息)` | 同上 |
| `warn(模組, 訊息)` | 同上 |
| `error(模組, 訊息)` | 同上 |

### 7.4 輸出格式

```
[2026-07-20 14:30:00] [INFO] [模組名稱] 訊息內容
```

層級過濾規則：低於設定層級的日誌不會輸出（例如 `LOG_LEVEL=info` 時，`debug` 層級不會顯示）。

### 7.5 檔案寫入機制

- 使用 `Deno.writeFile` 附加模式（`append: true, create: true`）
- 所有檔案寫入透過單一 Promise chain 序列化，不發生併發檔案鎖定
- 寫入錯誤以 `console.error` 記錄（不中斷應用程式流程）

### 7.6 使用範例

```typescript
import { info, error, logger } from '@dui/util';

info('MyGateway', '服務啟動完成');
error('MyGateway', '資料庫連線失敗');

// 直接使用 logger 實例
logger.warn('MyGateway', '記憶體使用率偏高');
```

## 8. Response — 統一 API 回應

### 8.1 概述

提供所有 Gateway 共用的 API 回應型別與建構函式。不含 Hono 依賴，純資料層級。

### 8.2 型別

| 型別 | 說明 |
|------|------|
| `ErrorCode` | 錯誤代碼常數（`NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`, `BAD_REQUEST`, `INTERNAL_ERROR`） |
| `SourceType` | 資料來源層級（`'L2'` \| `'L3'`） |
| `SuccessResponse<T>` | 成功回應：`{ success, data, source }` |
| `ErrorResponse` | 錯誤回應：`{ success, error: { code, message, status } }` |
| `ApiResponse<T>` | 聯集型別：`SuccessResponse<T> \| ErrorResponse` |
| `PaginationInfo` | 分頁資訊：`{ page, pageSize, total, totalPages }` |
| `PaginatedData<T>` | 分頁資料：`{ items, pagination }` |

### 8.3 建構函式

| 函式 | 說明 |
|------|------|
| `success(data, source?)` | 建立成功回應 |
| `paginated(items, pagination, source?)` | 建立分頁回應 |
| `errorRes(code, message, status)` | 建立錯誤回應 |
| `Errors.notFound(msg?)` | 404 錯誤便利建構 |
| `Errors.forbidden(msg?)` | 403 錯誤便利建構 |
| `Errors.validationError(msg?)` | 422 錯誤便利建構 |
| `Errors.badRequest(msg?)` | 400 錯誤便利建構 |
| `Errors.internalError(msg?)` | 500 錯誤便利建構 |

### 8.4 使用範例

```typescript
import { success, paginated, Errors } from '@dui/util';

// 成功回應
return c.json(success({ id: '1', name: 'foo' }));

// 分頁回應
return c.json(paginated(items, { page: 1, pageSize: 20, total: 100, totalPages: 5 }));

// 錯誤回應
return c.json(Errors.notFound('使用者不存在'), 404);
```

```json
    "@std/encoding/base64": "jsr:@std/encoding@^1.0.0/base64",
    "hono/jwt": "jsr:@hono/hono@^4.12.31/jwt"
  }
}
```

### exports — 子路徑匯出

所有公開模組皆透過子路徑匯出，Gateway 可直接引用特定模組：

```typescript
import { encrypt } from '@dui/util/crypto';
import { InnerAPI } from '@dui/util/InnerAPI';
import { verifyToken } from '@dui/util/jwt';
import { ConfigStore } from '@dui/util';           // 主入口匯出
```

### imports — 依賴說明

- `@std/path` — 跨平台路徑解析（`dirname()`）
- `@std/encoding/base64` — 標準 Base64 編解碼（`encodeBase64` / `decodeBase64`）
- `hono/jwt` — JWT 驗證用

```
├── response.ts             ← 統一 API 回應型別與建構函式
├── deno.json               ← 套件設定
└── docs/
    ├── 規格書.md           ← 本文件
    └── 版本紀錄.md         ← 版本歷史
```
