# @dui/database 規格書

> 最後更新：2026-08-02

---

## 1. 套件概述

`@dui/database` 是 WebCube2027 的資料庫抽象層，提供統一的資料存取介面，支援多種資料庫後端（Adapter 模式）。所有 Gateway 皆透過此套件操作資料庫，不直接依賴特定資料庫驅動。

**核心設計：Adapter Registry + Connection Pool。**

- 存入及取出資料均為純 JSON
- 無層級概念（L1/L2/L3），層級管理為 Gateway 層職責
- 採用 Registry Pattern 註冊 Adapter 工廠，無需 switch-case

### 相依關係

```
@dui/database
  ├── @dui/pool    ← 連線池基礎（BasePool：heartbeat / eviction / shutdown）
  └── @dui/util    ← 加解密（encrypt/decrypt）、日誌（info/error/debug/warn）
```

| Adapter | 類型 | 狀態 |
|---------|------|------|
| SurrealDB | 文件型／關聯式混合 | ✅ 已實作 |
| SQLite | 檔案型 | ✅ 已實作 |
| MongoDB | 文件型 | ✅ 已實作 |
| MySQL | 關聯式 | ✅ 已實作 |
| PostgreSQL | 關聯式 | ✅ 已實作 |
| Firestore | 雲端 NoSQL | ✅ 已實作 |
| Appwrite | 雲端 BaaS | ✅ 已實作 |
| DynamoDB | AWS NoSQL | ✅ 已實作 |
| MSSQL | Microsoft SQL Server | ✅ 已實作 |

Adapter 透過 Registry Pattern 註冊與建立，不再使用硬編碼 switch-case：

```typescript
// 註冊（模組層級自動執行）
registerAdapter('mysql', (options) => new MysqlAdapter(options as MysqlConnectOptions));
registerAdapter('pgsql', (options) => new PgsqlAdapter(options as PgsqlConnectOptions));
// ... 其餘 adapter 同理

// 建立（一行完成）
const adapter = createAdapter(type, options);
```

## 3. 架構

`@dui/database` 本身**不包含層級概念（L1/L2/L3）**。它是一個純粹的 Adapter 註冊中心與連線池，專注於：

- Adapter 工廠的註冊與建立（`registerAdapter()` / `createAdapter()`）
- 資料庫連線的生命週期管理（heartbeat、idle eviction、graceful shutdown）
- 統一的 `DatabaseAdapter` 介面抽象

層級管理（哪些連線是 SYSTEM、哪些是 tenant）、連線資訊的加解密儲存、查詢路由（L3 → L2 fallback、跨租戶合併）等職責，均由 **Gateway 層服務**（如 `data-gateway` 的 `DbManager`）負責。

### 3.1 Collection 階層

```
Collection (實際的 table/collection)
  ├── Model: 圖片     →  id = "圖片:圖片:xxxx"
  ├── Model: 標籤     →  id = "圖片:標籤:ssss"
  └── Model: 評論     →  id = "圖片:評論:cccc"
```

**Collection 是實際儲存的資料表**，每個 collection 可包含多種 model type，以 composite ID 的第二段區分。

### 3.2 資料庫 ID 規則

格式：`collection:model:nanoid`

- **collection** — 集合/表格名稱（實際存在的 table/collection）
- **model** — 資料型態名稱（區分同一 collection 下的不同類型）
- **nanoid** — 唯一識別碼（12 字元）

範例：`圖片:圖片:abc123def456`、`圖片:標籤:xyz789`、`使用者:管理員:aB3xK9mW2pQr`

## 4. 設定儲存（ConfigStore）

此套件不包含設定儲存實作。設定儲存由 `@dui/util` 的 `ConfigStore` 提供，為輕量 JSON 檔案 KV store，用於儲存：

- 加密金鑰
- L2 資料庫連線資訊（加密後）
- 其他系統設定

ConfigStore 的生命週期由呼叫方（如 `@dui/framework` 或 `data-gateway`）管理：

```typescript
import { ConfigStore } from '@dui/util';

const config = new ConfigStore(`${dataDir}/config.json`);
await config.init();
```

`ConfigStore` 非此套件職責，此處僅說明相依關係。

## 5. 資料池（AdapterPool）

### 5.1 架構概述

**AdapterPool** 是本套件的核心，繼承自 `@dui/pool` 的 `BasePool`，提供：

- **Adapter Registry**：透過 `registerAdapter(type, factory)` 註冊資料庫驅動工廠，`createAdapter(type, options)` 動態建立 Adapter 實例。新資料庫類型無需修改 Pool 核心。
- **連線池管理**：以字串 key 識別連線（如 `"SYSTEM"`、`"example.com"`），支援 persistent 旗標避免 idle eviction，內建 heartbeat 保持長連線。
- **生命週期 Hook**：`onFlush()`（no-op）、`onHeartbeat()`（對 persistent 連線發送輕量 `ping()`，未實作 ping 的 adapter 以 `count('_heartbeat_')` 後備）、`onEvict()`（關閉被驅逐的 idle 連線）。
- **優雅關機**：`shutdownAll()` 遍歷所有連線並呼叫其 `close()` 方法。

### 5.2 核心方法

| 方法 | 說明 |
|------|------|
| `registerAdapter(type, factory)` | 註冊資料庫 Adapter 工廠（靜態方法） |
| `createAdapter(type, options)` | 依註冊的工廠建立 Adapter 實例 |
| `set(key, adapter, isCold?, isPersistent?)` | 將連線放入池中 |
| `get(key)` | 依 key 取得連線，若已淘汰則回傳 `null` |
| `keys()` | 列出所有池中的 key |
| `delete(key)` | 移除並關閉指定連線 |
| `has(key)` | 檢查 key 是否存在於池中 |
| `size` | 當前池中連線數量 |
| `shutdownAll()` | 依序關閉所有連線並銷毀池 |
| `testConnection(info)` | 建立臨時 Adapter，以輕量 `ping()` 驗證連線可達（factory 已連線，不重複 connect） |
| `getStatus()` | 繼承自 `BasePool`，回傳 `PoolStatus` 完整快照（容量、命中率、錯誤等） |
| `resetMetrics()` | 繼承自 `BasePool`，歸零 hits/misses/evictions 計數器 |
| `getItemsOverview()` | 回傳 `AdapterPoolItemOverview[]`，每筆含 `dbType` + `isPersistent` |

> 查詢路由（L3 → L2 fallback、跨租戶合併）不在 AdapterPool 職責範圍內，由 Gateway 層的 `DbManager` 實作。

### 5.3 生命週期

```
Gateway 啟動流程（以 data-gateway 為例）：
  1. new ConfigStore(configPath) + await config.init()
  2. new DbManager(config)
  3. await dbManager.initL2()           // 從 ConfigStore 讀取 L2 資訊 → createAdapter → pool.set('SYSTEM', ...)
  4. await dbManager.initL3(host)       // 從 L2 SYSTEM 讀取租戶資訊 → createAdapter → pool.set(host, ...)
```

AdapterPool 本身只管理連線的存放與淘汰，不關心 key 的命名規則或語意。

**優雅關機**（通常在 Gateway 層註冊）：

```typescript
// 由 Gateway 層呼叫，非此套件直接處理
await pool.shutdownAll();
// 1. 依序關閉所有連線（L3 → L2）
// 2. 清除內部 Map
```

## 6. BaseModel（選用工具）

### 6.1 概述

`BaseModel` 是一個選用的基底類別，**非必須使用**。如果你需要在應用層建立 Model 實例，可以直接 `new 你的Model(data)`，不需要註冊到資料庫層。

### 6.2 內建欄位

| 欄位 | 型別 | 說明 |
|------|------|------|
| `id` | `string` | 複合 ID，格式 `collection:model:nanoid`；setter 支援部分格式（`type:id` 或僅 `id`）；getter 在 table 尚未設定時輸出 `type:id`（避免開頭冒號） |
| `tags` | `string[]` | 標籤 ID 集合 |
| `updatedAt` | `Date` | 最後修改時間戳；constructor 會驗證日期有效性，Invalid Date 自動回退為當前時間 |
| `table` | `string` (getter/setter) | 複合 ID 的 collection（表格）部分 |
| `type` | `string` (getter/setter) | 複合 ID 的 model type 部分 |

方法：

- `toJSON()` — **動態序列化**：透過 `Object.keys(this)` 自動收集子類別的所有自有屬性（跳過內部 `編號` 欄位），無需硬編碼欄位清單。回傳值包含 `id`、`tags`、`updatedAt`。
- `init()` — 初始化 hook，供子類別覆寫
- `setIdentity(table, type)` — 設定 table 與 type（僅在尚未設定時生效）

### 6.3 `sanitizePayload()` 公用函式

位於 `adapter-interface.ts`，供所有 Adapter 的 `update()` 統一使用：

```typescript
function sanitizePayload(
  data: Record<string, unknown>,
  id: string,
): Record<string, unknown> {
  const cleaned = typeof (data as any).toJSON === 'function'
    ? (data as any).toJSON()
    : { ...data };
  return { ...cleaned, id, updatedAt: new Date().toISOString() };
}
```

確保：
1. 若傳入 BaseModel 子類別，自動呼叫 `toJSON()` 序列化
2. 強制寫入 `id` 與 `updatedAt`，避免資料庫端缺少必填欄位

### 6.4 使用範例

```typescript
// 從 data-gateway 取得 JSON
const res = await fetch('/api/圖片/圖片:圖片:abc123');
const { data } = await res.json();  // data = { id: '...', tags: [...], ... }

// 選用：轉成 Model 實例（無需註冊）
import 圖片 from './models/圖片.ts';
const image = new 圖片(data);
console.log(image.網址);
```

## 7. Adapter 介面

所有資料庫 Adapter 須實作 `DatabaseAdapter` 介面（位於 `adapter/adapter-interface.ts`）：

```typescript
interface QueryOptions {
  limit?: number;
  offset?: number;
  /** 欄位篩選：field → value 配對，所有條件 AND 疊加。支援 dot notation 巢狀欄位路徑（如 "名稱.zh-tw"） */
  filter?: Record<string, string>;
  /** 排序欄位名稱（data JSON 中的路徑，如 "updatedAt"、"名稱.zh-tw"） */
  sort?: string;
  /** 排序方向 */
  order?: 'asc' | 'desc';
}

interface FieldFilter {
  field: string;
  value: string;
}

interface DatabaseAdapter {
  readonly type: string;
  getById(id: string): Promise<Record<string, unknown> | null>;
  list(collection: string, modelType?: string, options?: QueryOptions): Promise<Record<string, unknown>[]>;
  queryByField(collection: string, filter: FieldFilter, modelType?: string): Promise<Record<string, unknown>[]>;
  create(collection: string, id: string, data: Record<string, unknown>): Promise<Record<string, unknown>>;
  update(collection: string, id: string, data: Record<string, unknown>): Promise<Record<string, unknown>>;
  delete(id: string): Promise<boolean>;
  patch(collection: string, id: string, fields: Record<string, unknown>): Promise<Record<string, unknown> | null>;
  count(collection: string, modelType?: string): Promise<number>;
  ping?(): Promise<boolean>;  // 選用：輕量連線檢查（heartbeat / testConnection 使用，如 SELECT 1 / 原生 ping）
  initialize(collection: string): Promise<void>;
  listModelTypes?(collection: string): Promise<string[]>;  // 選用
}
```

**公用輔助函式（亦位於 `adapter-interface.ts`）：**

```typescript
// 統一清理 payload，所有 Adapter 的 update() 共用
function sanitizePayload(
  data: Record<string, unknown>,
  id: string,
): Record<string, unknown>;

// SQL 識別元安全驗證（表名／欄位路徑），僅允許 Unicode 字母（含中文）、數字、_、-、.
// 所有 SQL adapter 的 collection 與 filter.field 皆以此防護 SQL injection
function isSafeIdentifier(name: string): boolean;

// 轉義 LIKE 萬用字元（% / _），用於前綴比對
function escapeLike(value: string): string;
```

## 8. 回應格式

AdapterPool 與各 Adapter 的方法直接回傳純 JSON 資料，無額外包裝層：

- 成功時回對應型別（`Record<string, unknown>[]`、`Record<string, unknown> | null`、`boolean`、`number` 等）
- 失敗時拋出 `Error`（含文字訊息）
- 不涉及 QueryResult 包裝或資料來源標記

## 9. 錯誤處理

Adapter 層級操作失敗時直接拋出 `Error`，不含包裝層。

具體錯誤碼（如 `NOT_FOUND`、`CONNECTION_REFUSED` 等）為上層 API Gateway 的職責，不在此套件範圍內。

### 9.1 Adapter 錯誤日誌

各 Adapter 實作應使用 `@dui/util` 的 `info` / `error` 記錄操作失敗日誌，不應靜默吞掉例外。

**Adapter 層級安全防護：**

| Adapter | 防護機制 |
|---------|---------|
| SurrealDB | 所有 SQL 字串插值中的使用者輸入經 `esc()` 對單引號跳脫 (`'` → `\'`)；collection 與 filter.field 先經 `isSafeIdentifier()` 驗證（非法則回空值／throw） |
| MSSQL | collection 以 `isSafeIdentifier()` 驗證，另以 `safeModel`（`replace(/[^a-zA-Z0-9_]/g, '_')`）清理供 sys.tables 比對與索引命名，避免名稱碰撞與注入 |
| SQLite / MySQL / PostgreSQL / SurrealDB / MSSQL | 所有 SQL 方法的 collection 參數（含複合 ID 解析）皆以 `isSafeIdentifier()` 驗證，讀取類回空值、寫入類 throw；LIKE 前綴以 `escapeLike()` 轉義 `%`/`_` |
| 所有 SQL Adapter | `update()` 統一使用 `sanitizePayload()` 確保資料完整性 |

**Firestore adapter 已知限制：**

為避免 Firestore 複合索引缺失問題，`queryByField()` 在指定 `modelType` 時採用**兩階段查詢**：
1. 先以 `data.{field}` equality 查詢（不需要複合索引）
2. 在記憶體中過濾符合 `modelType` 的結果

這意味著掃描的資料量會比直接在 Firestore 端過濾大，但避免了在每個新的 filter + modelType 組合上建立索引。

若 `list()` 因缺少複合索引而失敗，錯誤訊息會明確指示使用者前往 GCP Console 建立對應索引。
