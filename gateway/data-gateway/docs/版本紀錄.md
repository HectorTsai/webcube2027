# data-gateway 版本紀錄

> 版本紀錄已從規格書獨立出來。以里程碑計數：每個里程碑 `+0.1.0`，初始 `0.1.0`。

| 版本 | 日期 | 說明 |
|------|------|------|
| 2.3.0 | 2026-08-06 | **Level batch 端點 + L1/Audit 進 Pool + Seed-sync 簡化**：新增 `PUT/PATCH/DELETE /api/{level}/`（跨 collection/model，依 composite ID 自動路由），刪除舊 `/:collection/:model/put.ts|patch.ts|del.ts` 共 9 檔（保留 get.ts/post.ts）。L1 與 Audit 皆移入 AdapterPool 管理（key `L1`/`AUDIT`，persistent），刪除 `services/l1-data.ts`、`audit.ts` 改委託 `dbm.Audit`。`seed-sync.ts` 不再依 collection:model 分組，改走 `PUT /api/{level}/` 單一端點。Pool 現含 4 筆：AUDIT + L1 + SYSTEM + l3test.localhost。 |
| 2.1.0 | 2026-08-05 | **批次 CRUD**：PUT/PATCH/DELETE `/api/:level/:collection/:model` 新增批次操作（body 為 JSON 陣列，單次最多 100 筆，逐筆驗證 id 並回報部分成功）；POST 同路徑 body 為陣列時批次建立（id 可省略自動產生，已存在者回報「請改用 PUT 覆寫」）；L1/L2/L3 三層共用統一 `utils/crud.ts`（`opts.layer='L1'` 指定操作 L1，原 `utils/l1-crud.ts` 已刪除）。批次回應格式含 `成功筆數/失敗筆數/成功/失敗/失敗原因`，審計日誌整批只寫一條。修正 `@dui/database` sqlite adapter 的 `delete` 回傳值（改以 `changes>0` 判定是否存在，與 mssql/mongodb 語意一致），批次刪除不存在的 id 會正確列入失敗。seed-sync（`@dui/framework`）改為依 `collection:model` 分組後以批次 PUT 覆寫，seed 同步的 HTTP 請求數由每筆一次降為每分組一次。 |
| 2.0.0 | 2026-08-03 | 移除 L2+L3 自動合併，回歸單層路由：`utils/crud.ts` 刪除 `mergeModels`、`scope=all`（`rest_path`）觸發的合併分支與 `listAll` 呼叫，`services/db-manager.ts` 刪除 `listAll` 方法；`handleCollection`／`handleList` 一律單層查詢（有 `effective_host` → L3，無 → L2）。L1/L2/L3 皆為純單層操作，gateway 需合併 L1/L2/L3 時自行 fetch 組合。route-loader 的 Pass 3 階層降級（`rest_path`）機制保留不動。規格書與 doc.md 同步更新。 |
| 1.9.0 | 2026-08-03 | setup 頁面修正與 Gateway 位址自動記錄：(1) **修復主控台語法錯誤**——SCRIPT 模板字串內 `replace(/\/+$/, '')` 的 `\/` 於反引號字串執行時被解譯成 `/`，導致渲染後 `//` 被視為註解、`)` 被吃掉、整個腳本無法執行，進而使類型切換監聽器失效、頁面永遠顯示 SQLite 的「資料庫檔名」欄位；改以 `endsWith()` 迴圈去除尾端斜線，避免模板字串跳脫陷阱。(2) **Master Key 新增確認輸入**：`master_key_confirm` 欄位，前端送出前比對兩次輸入一致。(3) **移除 auth-gateway URL**：`POST /api/setup` body 僅 `master_key`／`l2`，移除 ConfigStore `auth_gateway_url` 欄位、`main.ts` 的 `setAuthGatewayUrl()` 與 `@dui/util/jwt` 相依（deno.json import 一併移除）、health 的 `auth_gateway_url` 回傳；安裝完成卡改回「返回首頁」。(4) **Gateway 位址自動記錄**：`POST /api/register-gateway` 註冊成功後以請求來源位址（`new URL(c.req.url).origin`）寫入 ConfigStore `gateways` 表（`{ name: origin }`），health 改回傳 `gateways` 欄位供診斷。 |
| 1.8.0 | 2026-08-03 | setup 聚焦 L2 資料庫：確認 `POST /api/setup` 不建立任何帳號（body 僅 `l2`／`auth_gateway_url`／`master_key`），修正過時註解（移除「建立預設角色與管理員」與 inner API 描述）；安裝頁面 L2 連線帳密欄位改名為「資料庫帳號／資料庫密碼」並加註「非 WebCube 帳號」；安裝完成卡改為導向 auth-gateway 安裝頁（移除已刪除的 `/admin` 連結）。超管理者帳號由 auth-gateway setup 建立。 |
| 1.7.0 | 2026-08-03 | 移除 CRUD handler 殘留的角色權限檢查：`utils/crud.ts` 刪除 `jwt_payload` / `checkAccess` / self 作者過濾與自動填 `作者` 邏輯（含 self 檢查所需的多餘 getById），權限判定僅由各層 middleware 的 `X-API-Key` collection 權限表把關。權限工具（`PermissionMap` 等型別與 `checkPermission` / `checkAccess` / `mergePermissions` / `extractCollection`）統一搬移至 `@dui/framework` 的 permission 模組，刪除 data-gateway 與 auth-gateway 各自的 `utils/permission.ts` 複本；auth-gateway `verify-user` 改由 `@dui/framework` 匯入 `mergePermissions`。規格書 5.4「角色權限對照」改寫為「權限模型（Gateway 層級，無角色解析）」。 |
| 1.6.0 | 2026-08-03 | 連線池狀態監控：`/api/health` 新增 `pool` 欄位（AdapterPool 快照，含 `status` 統計與 `items` 逐連線明細），由 `db-manager.getPoolSnapshot()` 提供（`getStatus()` + `getItemsOverview()`）。首頁新增「連線池狀態」卡（連線數／常駐／命中率／未保存＋逐連線明細），並修正過時文案（多租戶識別改為 X-Tenant header、移除 JWT 金鑰輪換改為連線池管理）。修復 health 對已搬離之 `database/models/網站資訊介面` 的殘留 import（改為局部型別）。 |
| 1.5.0 | 2026-08-03 | 架構統一重構：(1) L1 API 結構與 L2/L3 同構（`_collection_/_model_/get.ts|post.ts`、`_collection_/get.ts`、`_id_/put.ts|patch.ts|del.ts`），由新 `utils/l1-crud.ts` 提供 handlers；刪除 `routes/api/l1/seed/post.ts`（`POST /inner-api/l1/seed`），L1 seed 改由 auth-gateway 安裝時以 L1 CRUD（`POST /api/l1/:collection/:model`）寫入。(2) L1/L2/L3 三層 middleware 統一：`extractCollection` 支援 composite ID（`使用者:角色:訪客` → 取第一段 `使用者`），移除 L2 的 `SPECIAL_PATHS`。(3) 刪除 `POST /api/l2/bulk-create`（`routes/api/l2/bulk-create/post.ts`）。(4) 刪除 admin/manager 頁面（`routes/_lang_/admin/`、`routes/_lang_/manager/`），首頁不需登入、直接顯示 L1/L2/L3 資料庫狀態。(5) `routes/_layout.tsx` 移除登入邏輯（navbar 僅顯示服務狀態 badge）；根 `routes/_middleware.ts` 移除 token/logout cookie 與 JWT 邏輯，只保留：公開路徑放行 → 安裝檢查 → L2 重連。(6) data-gateway 不再提供 `/api/me`（屬 auth-gateway，前端跨域呼叫）與 `/api/sites`（屬 site-gateway），`routes/api/me/`、`routes/api/sites/` 已刪除。(7) 移除 `routes/api/_middleware.ts`（僅解析 JWT），API 層只有 l1/l2/l3 各自的 X-API-Key middleware。規格書與開發者文件同步更新。 |
| 1.4.0 | 2026-08-03 | 移除 `POST /api/l2/create-admin` 內部端點：該功能已由 auth-gateway 的 `/api/register` 取代。`create-admin` 已從 L2 middleware 的 `SPECIAL_PATHS` 移除。端點檔案 `routes/api/l2/create-admin/post.ts` 已刪除。 |
| 1.3.0 | 2026-08-03 | 移除 `POST /api/role` 端點：auth-gateway 不再呼叫 data-gateway 的專用 role 端點，改為直接使用 L2 CRUD（`GET /api/l2/使用者:角色:訪客` 攜帶 `X-API-Key` header）查詢角色資料。移除內建 Inner API 路由目錄（`routes/inner-api/`）。規格書同步更新：移除所有 /api/role 與 inner-api 相關描述。 |
| 1.2.0 | 2026-08-03 | verify-user 搬遷：移除 `POST /inner-api/auth/verify-user` 端點（該功能已由 auth-gateway 本端 `/api/verify-user` 取代）；L3 middleware 新增 `X-Tenant` header 支援，可指定操作的租戶 domain，設為 `effective_host` 供下游 CRUD handler 路由至對應 L3 資料庫。規格書同步更新：移除所有 verify-user/inner-api 相關描述，更新 L3 middleware 行為說明。 |
