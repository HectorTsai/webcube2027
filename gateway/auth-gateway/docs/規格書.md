# auth-gateway 規格書

> 最後更新：2026-07-29

---

## 1. 概述

auth-gateway 是 WebCube2027 的**認證授權 Gateway**，負責處理使用者登入、JWT Token 簽發與驗證。為其他 Gateway 提供統一的身份驗證服務。

**核心職責**：

- 使用者登入（目前支援本地帳號密碼認證）
- JWT Token 簽發與驗證
- 提供 Token 驗證 API 供其他 Gateway 內部調用
- 健康檢查代理（代理 data-gateway 的健康狀態）

```

  │
  ├── createGateway()                   ← @dui/framework
  │     ├── L1 init (l1.json)            ← 資料目錄: ./data/
  │     ├── Crypto key init (存入 L1)    ← registerKey() 註冊
  │     ├── Hono app 建立
  │     └── 檔案路由載入 (routes/)
  │
  ├── 安裝檢查 Middleware               ← routes/_middleware.ts
  │     ├── 無 L1 data_gateway_url → 視為未安裝，僅允許 /setup、/api/setup
  │     ├── 允許公開路徑（/setup、/css/、/images/、/favicon、/health）
  │     ├── 允許公開 API（/api/setup、/api/anonymous-token、/api/jwt-public-key）
  │     └── /:lang/login 也允許未安裝時存取（但登入時仍會驗證 data-gateway）
  │
  ├── setup 流程 Middleware             ← routes/setup/_middleware.ts
  │     └── 設定「安裝模式」標記到 Context（c.set('setup_mode', true)）
  │
  ├── Ed25519 金鑰對管理
  │     ├── 檢查 L1 是否有 _jwt_private_key
  │     ├── 若不存在：呼叫 crypto.subtle.generateKey('Ed25519')
  │     │     ├── 匯出 PKCS#8（私鑰）→ hex → 存入 L1
  │     │     └── 匯出 SPKI（公鑰）→ hex → 存入 L1
  │     ├── 若已存在：從 L1 讀取 hex → importKey() 還原 CryptoKey
  │     └── 公鑰 hex 保留在記憶體供 /api/jwt-public-key 端點使用
  │
  ├── _layout.tsx 載入                 ← routes/_layout.tsx
  │     ├── 提供 Layout 元件（navbar + footer；navbar 顯示 data-gateway 健康狀態 badge）
  │     └── 提供 renderPage() 供 .md 文件使用
  │
  └── gw.start()                        ← 啟動 HTTP Server
```

### 3.1 使用 `@dui/framework`

auth-gateway 使用 `@dui/framework` 的 `createGateway()` 統一處理以下初始化：

1. **L1 KV Store** — 在 `gateway/auth-gateway/data/l1.json` 建立設定儲存
2. **加密金鑰** — 自動產生 256-bit 金鑰，存入 L1 的 `_crypto_key`，透過 `registerKey()` 註冊
3. **Hono 應用程式** — 建立 HTTP server
4. **檔案路由** — 自動載入 `routes/` 目錄下的頁面路由

### 3.2 Ed25519 金鑰對管理

auth-gateway 在啟動時會檢查 L1 中是否有 `_jwt_private_key`：

```typescript
async function getOrCreateKeyPair() {
  const storedPrivateHex = await gw.l1.get('_jwt_private_key');
  if (storedPrivateHex) {
    // 從 L1 還原金鑰對
    const privateKey = await crypto.subtle.importKey(
      'pkcs8', hexToBytes(storedPrivateHex), { name: 'Ed25519' }, false, ['sign'],
    );
    const publicKey = await crypto.subtle.importKey(
      'spki', hexToBytes(await gw.l1.get('_jwt_public_key')!), { name: 'Ed25519' }, false, ['verify'],
    );
    return { privateKey, publicKey };
  }
  // 產生新金鑰對
  const keyPair = await crypto.subtle.generateKey(
    { name: 'Ed25519' }, true, ['sign', 'verify'],
  ) as CryptoKeyPair;
  const pkcs8 = new Uint8Array(await crypto.subtle.exportKey('pkcs8', keyPair.privateKey));
  const spki = new Uint8Array(await crypto.subtle.exportKey('spki', keyPair.publicKey));
  await gw.l1.set('_jwt_private_key', bytesToHex(pkcs8));
  await gw.l1.set('_jwt_public_key', bytesToHex(spki));
  return { privateKey: keyPair.privateKey, publicKey: keyPair.publicKey };
}
```

JWT 使用 **EdDSA (Ed25519)** 非對稱演算法簽章，Token 有效期為 **24 小時**。

**安全特性**：
- 私鑰只存在 auth-gateway 的 L1 中，永不外洩
- 其他 gateway 透過 `GET /api/jwt-public-key` 取得公鑰進行本地驗證
- 支援金鑰輪換：重新啟動時若 L1 金鑰被更新，會自動使用新金鑰

## 4. 資料目錄

```
gateway/auth-gateway/
└── data/
    └── l1.json              ← L1 設定儲存
                                ├── _crypto_key（加密金鑰）
                                ├── _jwt_private_key（Ed25519 私鑰 PKCS#8 hex）
                                ├── _jwt_public_key（Ed25519 公鑰 SPKI hex）
                                └── data_gateway_url（data-gateway 服務 URL，安裝時設定）
```

auth-gateway **不涉及 L2/L3 資料庫操作**。使用者驗證透過 data-gateway 的內部 API（`/inner-api/auth/verify-user`）進行。

## 5. API 路由

### 5.1 安裝與設定 API

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/setup` | 首次安裝：設定 data-gateway URL、初始化 Ed25519 金鑰 |

安裝請求主體：

```json
{
  "data_gateway_url": "http://localhost:8002"
}
```

安裝流程：
1. 檢查是否已安裝（若 L1 已有 `_jwt_private_key` 則拒絕重複安裝）
2. 儲存 `data_gateway_url` 到 L1（供後續使用者驗證與健康檢查代理使用）
3. 產生 Ed25519 金鑰對（若尚未存在）
4. 回傳成功結果

> 此端點也接受選填欄位 `auth_gateway_url`（用於指定自身 URL），但預設從請求的 Host header 推斷。

### 5.2 訪客 JWT API

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/anonymous-token` | 簽發訪客 JWT（body: `{ domain }`），1 小時有效期，身份為 **訪客** 使用者，payload 含角色權限 |

請求主體：

```json
{
  "domain": "www.dui.com.tw"
}
```

處理流程：
1. 向 data-gateway 的 `POST /inner-api/role` 查詢訪客角色資料（含權限）
2. 將角色權限寫入 JWT payload 的 `權限` 欄位
3. 以 EdDSA (Ed25519) 簽發 JWT，1 小時有效期

訪客 JWT payload：

```json
{
  "tenant": "www.dui.com.tw",
  "sub": "使用者:使用者:訪客",
  "帳號": "訪客",
  "角色": ["使用者:角色:訪客"],
  "權限": {
    "l2": { "default": { "讀": false, "寫": false } },
    "l3": { "default": { "讀": true, "寫": false } }
  },
  "type": "visitor",
  "iat": 1718000000,
  "exp": 1718003600
}
```

> 訪客 JWT 代表**訪客**使用者身份，payload 攜帶完整的角色權限資訊，data-gateway 可直接讀取 `權限` 欄位進行存取控制，無需額外查詢。

### 5.3 認證 API

| 方法 | 路徑 | 說明 |
|------|------|------|
| POST | `/api/login` | 使用者登入（驗證帳號密碼，簽發已認證 JWT，payload 含角色權限） |
| GET | `/api/jwt-public-key` | 取得 Ed25519 公鑰（hex 編碼 SPKI 格式），供其他 gateway 本地驗證 |
| POST | `/api/verify` | Token 驗證（要求 body 傳入 token，回傳 payload 含權限） |
| GET | `/api/verify` | Token 驗證（從 Authorization Header 或 Cookie 讀取 token，回傳 payload 含權限） |

### 5.4 登入流程

```
POST /api/login
  │
  ├── localProvider.login(c)           ← 驗證帳號密碼（透過 data-gateway inner API）
  │     └── fetch POST /inner-api/auth/verify-user
  │           └── 回傳使用者資料 + 合併後的權限
  │
  ├── 若驗證成功：
  │     ├── sign JWT (EdDSA/Ed25519, 24h expiry)
  │     │     payload 包含：
  │     │       tenant, sub, 帳號, 角色, 權限, type: 'authenticated', iat, exp
  │     └── Set-Cookie: jwt=... (HttpOnly, SameSite=Lax)
  │
  └── 回傳 { success, data: { token, 帳號, 角色, 權限 } }
```

**登入請求主體**：

```json
{
  "帳號": "admin",
  "密碼": "password"
}
```

**登入成功回傳**（角色為陣列格式，含合併權限）：

```json
{
  "success": true,
  "data": {
    "token": "eyJhbGciOiJFZERTQSJ9...",
    "帳號": "admin",
    "角色": ["使用者:角色:超級管理員"],
    "權限": {
      "l2": { "default": { "讀": true, "寫": true } },
      "l3": { "default": { "讀": true, "寫": true } }
    }
  }
}
```

### 5.5 Token 驗證

其他 Gateway 可透過 `POST /api/verify` 或 `GET /api/verify` 驗證 JWT Token。

`POST /api/verify` 請求主體：

```json
{
  "token": "eyJhbGciOiJFZERTQSJ9..."
}
```

回傳：

```json
{
  "valid": true,
  "payload": {
    "sub": "使用者:使用者:admin",
    "帳號": "admin",
    "角色": ["使用者:角色:超級管理員"],
    "權限": {
      "l2": { "default": { "讀": true, "寫": true } },
      "l3": { "default": { "讀": true, "寫": true } }
    },
    "exp": 1234567890,
    "iat": 1234567890
  }
}
```

> 角色欄位為字串陣列，每個元素為 role ID（如 `使用者:角色:超級管理員`），支援一個使用者擁有多個角色。
> `權限` 欄位為合併多個角色後的權限地圖，data-gateway 可直接使用無需額外查詢。

```json
{
  "tenant": "www.dui.com.tw",
  "sub": "使用者:使用者:訪客",
  "帳號": "訪客",
  "角色": ["使用者:角色:訪客"],
  "權限": {
    "l2": { "default": { "讀": false, "寫": false } },
    "l3": { "default": { "讀": true, "寫": false } }
  },
  "type": "visitor",
  "iat": 1234567890,
  "exp": 1234571490
}
```

### 已認證 JWT

簽發於 `POST /api/login`，含 tenant、使用者身份與合併後的權限，用於完整 CRUD 操作。

```json
{
  "tenant": "www.dui.com.tw",
  "sub": "使用者:使用者:admin",
  "帳號": "admin",
  "角色": ["使用者:角色:超級管理員"],
  "權限": {
    "l2": { "default": { "讀": true, "寫": true } },
    "l3": { "default": { "讀": true, "寫": true } }
  },
  "type": "authenticated",
  "iat": 1234567890,
  "exp": 1234654290
}
```

> `tenant` 欄位存放 domain name（如 `www.dui.com.tw`），data-gateway 以此切換 L3 資料庫。
> `權限` 欄位為合併多個角色後的權限地圖，格式與 `utils/permission.ts` 的 `PermissionMap` 一致。

## 7. 使用者驗證流程

auth-gateway 本身**不儲存使用者資料**，使用者驗證委託給 data-gateway。使用者資料儲存在 `使用者` collection 中，以 model type `使用者` 區分使用者記錄與角色記錄。驗證成功後，data-gateway 會查詢使用者所有角色的權限並合併回傳。

```
auth-gateway                  data-gateway
    │                             │
    │  POST /inner-api/           │
    │  auth/verify-user           │
    │ ─────────────────────────► │
    │                             │── dataPool.queryByField('使用者', { field: '帳號', value }, '使用者')
    │                             │── bcrypt.compare(密碼, 密碼雜湊)
    │                             │── 查詢使用者所有角色，合併權限
    │ ◄────────────────────────── │
    │  { success, data: {         │
    │     帳號, 角色, 權限 } }     │
    │                             │
```

**使用者記錄結構**：

```json
{
  "id": "使用者:使用者:admin",
  "帳號": "admin",
  "密碼雜湊": "...",
  "角色": ["使用者:角色:超級管理員"],
  "updatedAt": "2026-07-22T..."
}
```

> 角色以 ID 陣列形式儲存，每個 ID 對應到 `使用者` collection 中的一筆角色記錄（model type = `角色`），角色名稱使用 `@dui/smartmultilingual` 的 MultilingualString 格式。角色記錄中包含 `權限` 欄位，auth-gateway 將權限寫入 JWT payload。

這種設計確保：
- 使用者資料統一由 data-gateway 管理
- auth-gateway 專注於認證邏輯與 Token 管理
- 權限資訊在 JWT 簽發時一併寫入，data-gateway 無需額外查詢即可進行存取控制
- 日後可擴充多種認證提供者（Provider）

## 9. 安全設計

- **JWT Token**：EdDSA (Ed25519) 非對稱簽章，24 小時有效期（訪客 JWT 為 1 小時）
- **HttpOnly Cookie**：防止 XSS 擷取 Token
- **非對稱金鑰對**：Ed25519 金鑰對自動產生，私鑰以 PKCS#8 格式 hex 編碼儲存於 L1，永不外洩
- **公鑰公開**：其他 gateway 透過 `GET /api/jwt-public-key` 取得 SPKI 公鑰進行本地驗證
- **金鑰輪換**：重新部署時更換 L1 金鑰即可立即生效
- **不儲存密碼**：使用者驗證委託 data-gateway，auth-gateway 不接觸密碼資料
- **權限內建於 JWT**：簽發 JWT 時自 data-gateway 查詢角色權限並寫入 payload，data-gateway 無需額外查詢即可進行存取控制，減少延遲與相依性
